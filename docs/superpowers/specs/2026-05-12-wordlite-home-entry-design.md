# WordLite 首页「今日学习入口」设计说明

## 1. 背景与依据

- **产品**：WordLite，面向小学生的无痛英语单词学习（固定节奏 + 间隔重复 + 轻游戏化）。
- **依据文档**：`WordLite_PRD.md`（每日队列、四步学习、检查点、奖励与家长页等）。本文档仅补充 **首页信息架构与主操作** 中 PRD 未逐字写明的部分；与 PRD 冲突时 **以 PRD 为准**，本文在 PRD 留白处做产品拍板。

## 2. 范围

- **在范围内**：今日学习入口页的布局、卡片职责、主按钮与副文案、与检查点/队列的关系、**当日会话已全部完成且无续学需求时** 的首页表现（见第 5 节）。
- **不在范围内**：四步题型细节、SRS 公式、家长页具体图表、皮肤资源美术稿（仍遵循 PRD 与现有实现）。

## 3. 首页布局（方案 B）

- 展示 **「新词」「复习」两块信息卡片**，用于呈现当日入队的 **新词数量** 与 **复习数量**（数量口径与 PRD「每日任务结构」一致：新词上限 5、复习抽样上限 8，实际入队数以算法结果为准）。
- 卡片 **仅作信息展示**，不作为「换一条学习路径」的入口（不替代 PRD 规定的队列顺序）。

## 4. 学习队列与主按钮（B1 + 方案 2 + 方案 C 主标题/副文案）

### 4.1 队列（B1）

- **唯一学习队列**：同一日会话内 **先新词、后复习**（与 PRD 4.1.1 一致）。
- **入口行为**：无论从何种 UI 进入学习，均从 **当前未完成位置** 继续（与检查点模型一致）；**不允许**通过「复习卡片」等 UI **跳过新词段** 进入复习段。

### 4.2 主操作（方案 2）

- 使用 **单独的主按钮** 进入学习流程；信息卡片 **不承担**「点击进入学习」的主职责（卡片是否可点见 4.3 可选说明）。

### 4.3 主按钮文案与进度（方案 C + 实现校准）

- **主标题**（与检查点 / 完成态关系）：
  - 存在 **当日活动检查点**（未跑完当日队列）时：**「继续学习」**。
  - **无检查点且非完成态**（尚未开始或已开始但无未清空检查点、且不处于第 5 节完成态）：**「开始学习」**。
  - **完成态（第 5 节）**：主入口弱化为次要按钮，文案为 **「再学一组」**（避免与「今日成就 / 已全部完成」同屏出现「开始学习」造成「还有未完成今日任务」的误读）。点击行为仍为调用 `startOrResumeSession` 并导航至学习页；若当日已无可学词，由 **SnackBar** 提示（见 5.2）。
- **进度副文案**（与统计卡 **「今日完成」** 口径对齐，避免「放弃会话」后出现「今日完成：2」与进度行「0 / y」矛盾）：
  - **有活动检查点**：`本会话：已完成 x / y`，其中 `x = checkpoint.wordIndex`，`y = 当日会话队列长度`（当前词未四步通关前 `wordIndex` 不前进）。
  - **无活动检查点且非完成态**：`进度：今日已通关 t / 计划 y 个词`，其中 `t` 为 **今日累计** 四步通关并结算词数（与统计卡一致），`y` 为 **当日计划队列总长** 预览（`todayQueuePreviewCounts.total`，与将生成的会话队列一致）。
  - **完成态**：在弱化主按钮附近展示 **「今日已通关 … · 本日计划共 …」** 式总结（与上款 `t`、`y` 同源）。
- **卡片点击（可选实现）**：若实现轻交互，仅允许 **非导航类** 反馈（如简短说明、展开今日队列预览）；**不得**产生与 B1 相冲突的「直达复习段」等行为。若不做点击反馈，亦符合本设计。

## 5. 当日会话已全部完成时的首页（方案 C）

**触发条件（产品口径）**：当日队列中 **x = y**（全部词已按四步完成并结算），且 **不存在** 需要「继续学习」的检查点状态（与 PRD「整段会话完成」语义一致）。**实现上** 以持久化标志（`wl_session_done_home_v1`）结合 `!hasActiveCheckpoint` 判定首页完成态，与上述语义一致。

**表现**：

- **弱化** 强调「进入今日学习」的主按钮：使用 **OutlinedButton「再学一组」**（不再作为视觉焦点，亦不使用「开始学习」四字）。
- 首页转为 **鼓励型与成就型入口**，例如突出：
  - **统计摘要**（与 PRD 家长/统计维度可呼应：如今日完成数、连续天数等，展示层级可较家长页更轻量）；
  - **奖励与收集物**（能量、碎片、皮肤档位等与 PRD 4.3 一致，仅作展示或跳转至已有奖励相关界面，不改变 SRS 规则）；
  - 可选：**明日再来**类轻提示（非强制推送）。
- **不引入** PRD 未定义的 **「无 SRS 后果的重复练词模式」** 作为默认完成态主路径（即不采纳「完成态仍强推进入学习」类 B 方案）。

### 5.2 完成态与「当日无可再学队列」的关系（修订）

- **旧表述（已废止）**：曾考虑用「`buildTodayQueue` 为空则关闭完成态」与 SnackBar 互斥，以免与「暂无可学单词」抢焦点。
- **现口径**：`shouldShowHomeSessionCompleteCelebration` 仅依赖 **「整段会话已成功结束」持久化标志** 与 **「无活动检查点」**。因此，在 **当日队列因进度已全部掌握等原因暂时为空** 时，**仍可出现** 完成态鼓励 UI（用户刚跑完一整段、当日已无新任务属合理情况）。
- 用户点击 **「再学一组」** 后，若 `startOrResumeSession` 仍无法生成检查点，则 **仅此时** 通过 SnackBar 提示「暂无可学单词…」，与完成态展示 **不矛盾**。

## 6. 验收要点（首页专项）

- 有/无检查点时，主标题与进度副文案 **与真实进度、检查点状态及「今日完成」统计一致**（本会话行 vs 今日累计行区分清晰）。
- 新词/复习卡片数量与 **当日队列生成结果 / 当日检查点队列** 一致。
- 完成态（第 5 节）下，主操作 **不为「开始学习」**；奖励与统计展示 **不与 PRD 计数定义矛盾**。
- 整段会话结束后，**允许** 在 `buildTodayQueue()` 为空时仍展示完成态；再次进入学习时若无队列则仅 SnackBar 提示（见 5.2）。

## 7. 首页入口实现状态（验收标记）

对照上文 §3～§6 与 `lib/screens/home_screen.dart`，**必选入口与状态均已实现**，可视为首页专项闭环。

| 验收项 | 状态 | 说明 |
|--------|:----:|------|
| 新词 / 复习数量预览（与当日队列或检查点一致） | ✅ | `_QueuePreviewRow` + `todayQueuePreviewCounts` |
| 单独主按钮进入学习（卡片不承担主路径） | ✅ | `FilledButton` / `OutlinedButton` + `startOrResumeStudy` |
| 主标题三态：开始学习 / 继续学习 / 再学一组 | ✅ | `primaryLabel` + `slice.hasActiveCp` / `slice.celebrate` |
| 进度副文案三态（本会话 x/y · 今日 t/计划 y · 完成态总结） | ✅ | `_progressSubtitle` |
| 完成态（C）：弱化主按钮、成就型统计卡强调 | ✅ | `celebrate` 分支 + `_HomeStatsCard(emphasize)` |
| 完成态下仍可展示；再学一组时空队列 SnackBar | ✅ | `startOrResumeSession` 后 `checkpoint == null` |
| 放弃 / 重置今日会话（可选操作） | ✅ | `_AbandonSessionButton` + `abandonCheckpoint` |
| 家长观察入口（AppBar） | ✅ | `ParentScreen` 路由 |
| 底部轻量提示文案 | ✅ | 「提示：每天约 5 分钟…」 |
| 队列卡片可点交互（§4.3 可选） | ✅ | 轻点新词/复习卡 → `showModalBottomSheet` 只读入队列表与说明，**不导航**、不改变 B1 顺序 |

**单测**：`test/home_screen_test.dart` 覆盖检查点主按钮、完成态按钮类型、队列预览数字、**队列卡片只读弹层**等。
